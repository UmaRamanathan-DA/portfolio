1. Phase 1 vs Phase 2 — What Changes

Phase 1 (current prototype)

  • Single-turn NL query → RAG → LLM answer
  • User must know what to ask
  • No multi-step analysis
  • Text UI only
  • RAG is the entire brain

Phase 2 (agentic extension)

  • Goal-oriented session → plan → tools → synthesis
  • Copilot proposes next analyses
  • Chains metric lookup + benchmark + recommendation
  • Optional voice in / voice out
  • RAG becomes one tool among several

2. Product Vision

DORA DevOps Copilot helps engineering leaders and platform teams understand delivery performance through conversational, multi-step analysis — not just answering “what is our CFR?” but “how is our deployment performance this quarter, where are we vs industry, and what should we fix first?”

Example goal: “Review our Q2 DORA performance and tell me the top bottleneck.”
The copilot fetches metrics → compares benchmarks → retrieves best-practice guidance → ranks improvement actions → returns a concise briefing (spoken or written).

4. Agent Capabilities (7 tools)

4.1 get_dora_metrics

Reads deployment frequency, lead time for changes, change failure rate (CFR), and mean time to restore (MTTR) from CSV/API for a given period or team.

Why agentic: Copilot decides which metrics to pull based on the user goal — not the user spelling out every metric.

4.2 compare_benchmark

Maps current values to DORA performance tiers (Elite / High / Medium / Low) using industry reference bands.

Output: “CFR 18% — below High tier target (≤10%).”

4.3 rag_best_practices (Phase 1 RAG, repackaged)

Retrieves DevOps/DORA guidance from embedded docs (Sentence Transformers + vector store). Phase 1 RAG logic moves here as a tool, not the whole app.

4.4 analyze_trend

Compares current period vs prior period; flags improving / degrading metrics.

4.5 identify_bottleneck

Ranks metrics by gap-to-target and trend severity; returns top 1–3 focus areas with rationale.

4.6 generate_action_plan

Produces 3–5 prioritised recommendations grounded in tool outputs (not hallucinated metrics).

4.7 format_briefing

Formats response for channel: voice (≤45 sec, short sentences) or dashboard (structured markdown + numbers).

8.2 New API contract

POST /agent Request: { "message": "Review Q2 DORA performance", "session_id": "...", "channel": "text|voice" } Response: { "answer": "...", "metrics_used": ["cfr", "deployment_frequency"], "tools_called": ["get_dora_metrics", "compare_benchmark", "identify_bottleneck"], "follow_ups": ["Want a breakdown by team?"], "voice_summary": "..." // optional short form for TTS }

8.3 Orchestrator loop (conceptual)

def run_agent(user_message, session): intent = classify_intent(user_message, session) plan = build_tool_plan(intent) # e.g. [get_dora_metrics, compare_benchmark, ...] tool_results = [] for step in plan: result = execute_tool(step, session) # returns structured JSON, not prose tool_results.append(result) if result.requires_clarification: return ask_clarifying_question(result) answer = synthesize_with_llm(user_message, tool_results) # Ollama/LLaMA 3 return format_briefing(answer, channel=session.channel)

8.4 What stays from Phase 1

  • Flask app shell, deployment (Render/Railway)
  • Ollama + LLaMA 3 for generation
  • Sentence Transformers + RAG corpus (now invoked via rag_best_practices tool)
  • Pandas/CSV metric loading
  • Existing UI screenshot / dashboard — extended with agent chat panel

8.5 What Phase 2 adds

  • Agent orchestrator with tool calling and session memory
  • Structured metric tools (grounding — reduces hallucination)
  • Multi-step plans for complex questions
  • Follow-up suggestions
  • Voice input/output hooks
  • Logging: tools called, metrics referenced (audit/debug)

9. Guardrails

  • Metrics must come from tools — LLM cannot invent CFR/MTTR numbers; synthesis only uses tool_results JSON.
  • Citation for best practices — RAG tool returns source snippets; copilot references them in recommendations.
  • Confidence fallback — if intent unclear, ask clarifying question instead of guessing.
  • Voice brevity — voice responses capped at ~3 sentences unless user asks for detail.
  • Human review — action plans labelled as “suggested”; not auto-applied to CI/CD systems.
